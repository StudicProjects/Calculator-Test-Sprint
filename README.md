# Calculator-Test-Sprint

HTTP API калькулятора с сохранением истории вычислений в PostgreSQL.

## Общие сведения

- Базовый URL: `http://localhost:<APP_PORT>`. Порт задаётся переменной окружения `APP_PORT`; значения по умолчанию нет.
- В примерах используется порт `8080`; замените его на порт своего сервера.
- Префикса `/api` нет. Авторизация не требуется.
- Запросы с телом передаются в JSON. Рекомендуемый заголовок: `Content-Type: application/json`; сервер не проверяет его значение.
- Успешные ответы и ошибки обработчиков имеют `Content-Type: application/json`.
- Имена JSON-полей приведены в таблицах ниже. Числовой результат вычисления передаётся **строкой**.

## Эндпоинты

| Метод | Путь | Назначение | Успешный ответ | Ошибки |
| --- | --- | --- | --- | --- |
| `POST` | `/eval` | Вычислить выражение и сохранить результат в историю | `200`, объект `EvalExpressionResponse` | `400`: `ValidationError`, `BadExpression`, `ExpressionLengthLimitExceeded`; `500`: `InternalError` |
| `GET` | `/history` | Получить всю историю вычислений | `200`, массив `HistoryRecord` | `500`: `InternalError` |
| `HEAD` | `/history` | Получить статус и заголовки ответа истории | `200`, без тела | `500`, без тела |

`HEAD /history` поддерживается автоматически маршрутизатором Go для маршрута `GET /history`: обработчик обращается к базе, но HTTP-сервер не отправляет тело ответа.

### POST /eval

Параметров пути и query-параметров нет.

#### Модель запроса: EvalExpressionRequest

| Поле | Тип JSON | Обязательность | Описание |
| --- | --- | --- | --- |
| `expression` | `string` | Нет в текущей реализации | Выражение длиной не более 256 байт. Отсутствующее поле или `null` трактуется как пустая строка. |

Пример:

```bash
curl -i -X POST 'http://localhost:8080/eval' \
  -H 'Content-Type: application/json' \
  -d '{"expression":"(2+4)/6"}'
```

#### Модель ответа: EvalExpressionResponse

Статус: `200 OK`.

| Поле | Тип JSON | Описание |
| --- | --- | --- |
| `expression` | `string` | Исходное выражение без нормализации или удаления пробелов. |
| `result` | `string` | Результат вычисления. Для пустого выражения возвращается пустая строка. |

```json
{
  "expression": "(2+4)/6",
  "result": "1"
}
```

#### Правила вычисления

- Допускаются цифры `0-9`, знаки `+`, `-`, `*`, `/`, круглые скобки, точка и ASCII-пробельные символы: пробел, табуляция, перевод строки, возврат каретки, перевод страницы. Фильтр: `^[0-9+\-*/().\s]+$`. После фильтра выражение разбирается библиотекой `expr`; допустимый набор символов сам по себе не гарантирует корректное выражение.
- Лимит проверяется через `len(expression)` в Go, то есть в байтах UTF-8 после декодирования JSON. Для разрешённых ASCII-символов это также число символов.
- Проверки выполняются по порядку: пустая строка, длина, допустимые символы, вычисление, сохранение в базу. Поэтому слишком длинное выражение с недопустимыми символами вернёт `ExpressionLengthLimitExceeded`.
- Пустая строка возвращает `{"expression":"","result":""}` и не сохраняется в историю. Так же обрабатываются `{}`, `{"expression":null}` и тело `null`. Полностью отсутствующее тело запроса вызывает `ValidationError`.
- Строка из одних пробелов не считается пустой и вызывает `BadExpression` при разборе.
- Деление на ноль не является ошибкой API: `1/0` возвращает `"+Inf"`, `-1/0` возвращает `"-Inf"`, `0/0` возвращает `"NaN"`. Такие результаты сохраняются в историю.
- Успешное непустое вычисление сохраняется до отправки ответа. Ошибка сохранения приводит к `500 InternalError`, даже если само вычисление успешно. Каждый повторный успешный запрос создаёт отдельную запись.
- Неизвестные поля JSON игнорируются. Декодируется только первое JSON-значение в теле; отсутствие дополнительных данных после него не проверяется.

### GET /history

Тело запроса, параметры пути и query-параметры не требуются. Фильтрации и пагинации нет.

```bash
curl -i 'http://localhost:8080/history'
```

Статус: `200 OK`. Ответ представляет собой массив объектов `HistoryRecord`, без обёртки.

#### Модель элемента ответа: HistoryRecord

| Поле | Тип JSON | Описание |
| --- | --- | --- |
| `expression` | `string` | Сохранённое исходное выражение. |
| `result` | `string` | Сохранённый результат вычисления. |

Поле `ID` существует только во внутренней модели и базе данных; в JSON оно не передаётся. Записи отсортированы по `id DESC`: сначала последние добавленные. История общая для всех клиентов.

```json
[
  {
    "expression": "1/0",
    "result": "+Inf"
  },
  {
    "expression": "(2+4)/6",
    "result": "1"
  }
]
```

При отсутствии записей:

```json
[]
```

## Ошибки API

Все ошибки обработчиков основаны на модели `CalculatorError`. Поля не вложены в дополнительный объект `error`.

| Поле | Тип JSON | Описание |
| --- | --- | --- |
| `type` | `string` | Один из четырёх типов ошибок, перечисленных ниже. |
| `message` | `string` | Описание ошибки. Текст может зависеть от JSON-декодера, библиотеки вычислений или драйвера БД; клиенту следует ориентироваться на статус и `type`. |

### 400 ValidationError

Эндпоинт: `POST /eval`.

Возникает при ошибке чтения или декодирования тела: пустое тело, некорректный JSON, несовместимый тип верхнего уровня (например, массив) или неверный тип поля `expression` (число, boolean, объект, массив).

Модель: только `type` и `message`.

Ответ на запрос без тела:

```json
{
  "type": "ValidationError",
  "message": "EOF"
}
```

Ответ на `{"expression":123}`:

```json
{
  "type": "ValidationError",
  "message": "json: cannot unmarshal number into Go struct field EvalExpressionRequest.expression of type string"
}
```

### 400 BadExpression

Эндпоинт: `POST /eval`.

Возникает, если выражение содержит недопустимые символы, имеет неверный синтаксис или библиотека вычислений возвращает ошибку.

Дополнительное поле:

| Поле | Тип JSON | Описание |
| --- | --- | --- |
| `expression` | `string` | Исходное выражение, вызвавшее ошибку. |

Ответ на `{"expression":"2+a"}`:

```json
{
  "type": "BadExpression",
  "message": "expression contains invalid characters",
  "expression": "2+a"
}
```

Ответ на `{"expression":"1+"}`:

```json
{
  "type": "BadExpression",
  "message": "unexpected token EOF (1:2)\n | 1+\n | .^",
  "expression": "1+"
}
```

### 400 ExpressionLengthLimitExceeded

Эндпоинт: `POST /eval`.

Возникает, если длина декодированного выражения превышает 256 байт.

Дополнительные поля:

| Поле | Тип JSON | Описание |
| --- | --- | --- |
| `expression` | `string` | Полное исходное выражение. |
| `length` | `integer` | Фактическая длина выражения в байтах UTF-8. |
| `limit` | `integer` | Допустимый максимум: `256`. |

Формат сообщения: `expression length <length> exceeded <limit> characters`. Несмотря на слово `characters`, длина считается в байтах.

Пример ответа для строки из 257 единиц:

```json
{
  "type": "ExpressionLengthLimitExceeded",
  "message": "expression length 257 exceeded 256 characters",
  "expression": "11111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111",
  "length": 257,
  "limit": 256
}
```

### 500 InternalError

Эндпоинты: `POST /eval`, `GET /history`.

Возникает при ошибке сохранения или получения истории, включая ошибки запроса к PostgreSQL, чтения записей и отмену контекста, а также при иных ошибках, не относящихся к трём типам выше.

Модель: только `type` и `message`. Сервер передаёт текст исходной ошибки; фиксированного сообщения нет. Ниже иллюстративный пример, фактический текст зависит от причины:

```json
{
  "type": "InternalError",
  "message": "database unavailable"
}
```

## Ошибки маршрутизации

Эти ответы формирует стандартный маршрутизатор Go. Они имеют `Content-Type: text/plain; charset=utf-8` и не используют модель `CalculatorError`.

| Статус | Причина | Тело ответа |
| --- | --- | --- |
| `404 Not Found` | Незарегистрированный путь, например `/unknown`, `/api/eval`, `/eval/` или `/history/`. | `404 page not found\n` |
| `405 Method Not Allowed` | Неподдерживаемый метод для существующего пути, например `GET /eval` или `POST /history`. | `Method Not Allowed\n` |

В ответе `405` также передаётся заголовок `Allow: POST` для `/eval` или `Allow: GET, HEAD` для `/history`. Отдельных обработчиков `OPTIONS` и CORS нет; `OPTIONS` для этих путей также возвращает `405`.

Здесь описаны ответы прикладных обработчиков и маршрутизатора. Ошибки транспорта или некорректного HTTP на уровне сервера не используют JSON-контракт API.
